## Scénario

`dc01.corp.lab` (10.10.0.10) est le contrôleur de domaine d'une petite entreprise fictive. Un accès utilisateur standard sur le domaine t'a été fourni. Ta mission : suivre la méthodologie du cours Active Directory & Windows pour remonter jusqu'aux droits Domain Admin.

## Objectifs

1. Identifier un compte de service disposant d'un SPN et récupérer son ticket Kerberos (Kerberoasting)
2. Exploiter un droit GenericAll mal attribué pour atteindre un compte Domain Admin

## Indices

- Énumère les comptes disposant d'un Service Principal Name (SPN) avec `GetUserSPNs.py` — l'un d'eux protège un service peu surveillé avec un mot de passe faible. Si la demande automatique de ticket (`-request`) échoue avec une erreur Kerberos, obtiens le ticket via `kinit`/`kvno` puis extrais le hash avec `describeTicket.py` — le résultat est identique, cassable avec John/Hashcat.
- Ton compte est membre d'un groupe qui dispose d'un droit `GenericAll` sur un second compte de service, lui-même membre de Domain Admins. Ce droit peut être abusé directement en LDAP (`ldapsearch`/`ldapmodify`) pour réinitialiser le mot de passe de ce compte, sans avoir besoin d'un outil dédié.

<TipCallout>
Ce lab reprend directement les chapitres 3 (Kerberos, Kerberoasting) et 2 (énumération AD) du cours Active Directory & Windows — la méthodologie complète y est détaillée pas à pas. Contre ce contrôleur de domaine Samba, certains outils Kerberos/LDAP orientés Windows (comme la collecte automatisée BloodHound) peuvent rencontrer des incompatibilités protocolaires : les mêmes objectifs restent atteignables avec les outils LDAP et Kerberos standards.
</TipCallout>

<WarningCallout>
Comme en mission réelle, documente chaque étape de ton raisonnement : un chemin d'attaque BloodHound n'a de valeur que si tu peux l'expliquer clairement dans un rapport (rappel du cours Rédaction de Rapports).
</WarningCallout>
