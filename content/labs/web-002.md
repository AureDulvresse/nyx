## Scénario

`app.lab` (10.10.0.10) est une application de gestion interne utilisée par une PME fictive. Le développement s'est concentré sur les fonctionnalités, pas sur la sécurité : trois failles distinctes s'enchaînent pour mener jusqu'au compte administrateur. Ta mission : les identifier et les exploiter dans l'ordre logique.

## Objectifs

1. Exploiter un XSS stocké pour exfiltrer un cookie de session
2. Bruteforcer un compte utilisateur via le formulaire de connexion
3. Exploiter une IDOR pour accéder au panneau d'administration

## Indices

- Le premier flag se trouve en injectant un payload JavaScript dans un champ de commentaire ou de profil persistant.
- Le formulaire de connexion ne limite ni le nombre de tentatives, ni n'affiche de CAPTCHA — Hydra est ton ami.
- Une fois connecté avec un compte utilisateur standard, examine attentivement les identifiants numériques présents dans les URLs de l'application.

<TipCallout>
Ce lab reprend directement les techniques vues dans les chapitres 4 (XSS), 5 (Authentification) et 6 (IDOR) du cours Sécurité Web (OWASP) — n'hésite pas à y retourner si tu bloques sur une étape précise.
</TipCallout>

<WarningCallout>
Chaque flag correspond à une technique distincte — résous-les dans l'ordre proposé, chaque étape prépare la suivante.
</WarningCallout>
