## Scénario

`api.lab` (10.10.0.10) expose une API REST de gestion de commandes utilisée par une application mobile fictive. L'équipe de développement a livré rapidement, sans appliquer les principes du cours Sécurité des Applications et des API : deux failles caractéristiques des API modernes t'attendent.

## Objectifs

1. Exploiter un défaut de contrôle d'accès au niveau des objets (BOLA) pour accéder à la commande d'un autre utilisateur
2. Forger un jeton JWT valide en exploitant une vérification d'algorithme mal implémentée

## Indices

- Authentifie-toi normalement, récupère l'identifiant de ta propre commande, puis modifie simplement cet identifiant dans l'URL de la requête API.
- Décode l'en-tête du JWT que l'API t'a délivré — si le serveur accepte un jeton dont l'en-tête indique l'algorithme "none", aucune signature n'est nécessaire pour le falsifier.

<TipCallout>
Ce lab reprend directement les techniques des chapitres 2 (OWASP API Security Top 10, BOLA) et 3 (JWT) du cours Sécurité des Applications et des API — relis-les si tu bloques sur une étape.
</TipCallout>

<WarningCallout>
Résous les deux flags dans l'ordre : comprendre la structure de l'API via le premier flag facilite la construction du jeton falsifié pour le second.
</WarningCallout>
