## Scénario

`shop.lab` (10.10.0.10) propose à ses vendeurs partenaires une fonctionnalité d'import de fiche produit au format XML pour ajouter leurs articles en masse. Ce point d'entrée traite le XML fourni sans désactiver les entités externes — une négligence classique qui transforme un simple champ d'import en porte d'accès au système de fichiers du serveur.

## Objectifs

1. Identifier le point d'entrée XML vulnérable et confirmer qu'il traite les entités externes (XXE)
2. Lire le contenu d'un fichier sensible du serveur via une entité XML externe
3. Extraire les identifiants de configuration exposés par ce fichier pour valider le flag final

## Indices

- Le parseur XML utilisé par le point d'import n'a pas désactivé le traitement des `DOCTYPE`/`ENTITY` externes.
- Une entité définie dans un `DOCTYPE` peut pointer vers un fichier local du serveur (`file:///...`) et être réinjectée dans la réponse affichée.
- `/etc/passwd` fait une bonne première preuve de concept avant de viser un fichier de configuration applicative plus intéressant.
