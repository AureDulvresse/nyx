## Scénario

Une boutique en ligne fictive tourne sur le serveur `shop.lab` (10.10.0.10). Le propriétaire soupçonne une intrusion en cours mais n'a aucune preuve concrète. Ta mission : reproduire l'attaque de bout en bout pour comprendre l'étendue de la compromission possible.

## Objectifs

1. Identifier une injection SQL exploitable sur le formulaire de recherche produit
2. Extraire les identifiants administrateur depuis la base de données
3. Uploader un web shell via le panneau d'administration
4. Escalader tes privilèges jusqu'à root

## Indices

- Le formulaire de recherche ne filtre pas correctement les apostrophes.
- Le panneau d'administration accepte l'upload de fichiers `.php` sans vérification stricte du type MIME.
- Une tâche cron s'exécute périodiquement avec les droits root — regarde du côté de `/etc/cron.d`.

<WarningCallout>
Cet environnement est isolé dans un réseau Docker dédié à ta session. Toute action ici reste strictement confinée à ce lab.
</WarningCallout>
